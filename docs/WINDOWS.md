# Windows 使用与开发

Windows 客户端使用 C# / .NET 10 / Windows Forms，与 macOS 的 Swift / AppKit 适配层并列。没有第三方 UI、图像或更新库。拼接算法按 Swift 实现移植，两端消费 `Tests/Fixtures/stitch-vectors.json` 的相同字节与预期结果。

## 安装与使用

- 支持 Windows 11，提供 x64（Intel / AMD）和 ARM64 包。自带运行时，无需另外安装 .NET。
- 下载对应的 ZIP，**完整解压到自己的可写目录**，运行 `Screenshot.exe`；不要直接从 ZIP 内运行。程序常驻系统托盘，双击托盘图标打开设置。
- 默认 `Ctrl+Shift+2` 区域截图，`Ctrl+Shift+7` 长截图；可以在设置中录入新组合键。被系统或其他应用占用时会提示，可用托盘菜单截图。
- 普通截图先冻结画面，再拖动框选。编辑器支持裁剪、箭头、矩形、圆形、文字、实心打码、颜色、线宽、撤销与重做。回车完成复制，Esc 取消，Ctrl+C 仅复制，Ctrl+S 保存 PNG。
- 长截图框选单屏正文，在原应用中向下滚动。边框穿透鼠标，预览不主动抢焦点，控件始终放在选区外。需要在选区旁留出空间；没有空间时请缩小选区。
- 长图回车 / ✓ 直接复制，✎ 编辑，↓ 复制并保存，× / Esc 取消；更多菜单提供重试、撤销、跟随末尾。临时按键冲突时使用预览按钮。

## 更新与安全提示

从托盘选择“检查更新”，确认后下载 GitHub 最新正式版中对应架构的安装包。严格验证仓库、正式版本、下载地址、大小、SHA-256、ZIP 文件范围、程序版本和架构；不接受 ZIP 中附带的脚本或任意目录。没有可用的 Windows 正式版资源时会提示，不安装 macOS 包或其他架构。

更新助手使用当前程序的副本，校验任务后等待旧进程退出。只替换程序、许可证和第三方声明，其他文件不动；保留 `.backup-*`，替换或启动失败时尝试回滚。只写当前用户可写目录，不自动提权；管理员权限运行时禁用自动更新，避免高权限助手使用用户可写的更新缓存。更新准备目录位于本机应用数据目录，不保存截图。

Windows 构建**尚未做 Authenticode 签名**，SmartScreen 可能提示来源不明。仅从本项目 GitHub 正式版下载，核对来源并按系统提示处理；不要关闭 SmartScreen、防病毒或其他系统保护。更新保留互联网来源标记。SHA-256 是完整性检查，不能代替发布者签名，也不能抵御维护者账号被攻破。未来可接入发布者证书，私钥不得提交到仓库。

## 支持边界

- Windows 首版提供原生编辑窗口，尚未完全复刻 macOS 的原位浮动工具栏；不支持悬停预选窗口、拖边框扩选及向上扩展长图。
- 采集适配器使用 Windows GDI 屏幕复制，坐标按 Per-Monitor V2 DPI 处理；普通截图可跨屏，显示器间空隙取决于桌面布局。普通截图在显示器布局变化时取消；长图保留已确认部分并提示重新框选。
- 固定栏、动画、悬浮元素、重复纹理、页面重排和动态聊天可能导致无法接续。请回到预览末尾附近，向下滚动；不会自动跳过缺失区域。锁屏、受保护内容、HDR、远程桌面或游戏独占全屏不作兼容性承诺。
- 普通截图最大 2400 万像素；长图最大 30000 行 / 2400 万像素 / 128 MiB 保留片段与匹配帧。最终合成、剪贴板和编辑还需要额外内存。只保留新增条带，采集与匹配一次只处理一帧，慢处理会丢弃采样机会。
- 关闭后释放图像；不会自动保存截图，不采集音频，不要求管理员、麦克风或额外输入监控权限。用户主动检查更新才联网。剪贴板历史和同步目录由系统及第三方工具管理。

## 开发与构建

开发需要 .NET 10 SDK、PowerShell 7；`make` 是统一可选入口，Windows 没有 make 时可直接运行对应 PowerShell 命令。

```sh
make windows-test
make windows-dev                         # 开发版默认 Ctrl+Alt+2 / 7，与日常版独立
make windows-build                       # x64 自包含 ZIP
make windows-build WINDOWS_RUNTIME=win-arm64
```

再次执行开发运行命令会重启当前工作区的开发副本（未导出的开发截图不会保留），不停止日常版或其他工作区的程序。

等价命令：

```powershell
dotnet run --project platforms/windows/Screenshot.Tests -c Release
./scripts/build-windows.ps1 -Development -Launch
./scripts/build-windows.ps1 -Runtime win-x64
./scripts/build-windows.ps1 -Runtime win-arm64
```

Windows CI 提供 x64、ARM64 便携包。x64 除原生编辑/PNG/剪贴板自测外，还以自身生成的窗口验证真实 GDI 采集、长图会话、控件排除、反向恢复、撤销、快捷键冲突和资源释放；没有交互桌面时明确失败，不将其当作通过。ARM64 在 x64 runner 上交叉构建，不能据此声称已完成 ARM64 真机验收。发布标签后，两平台构建全部成功才创建 Release，官网随后部署。Windows 自动更新使用带版本名 ZIP 及每架构校验清单，官网固定名下载入口另保留一个内容相同的 ZIP。

## 人工验收（真实 Windows 桌面必测）

1. 在 Windows 11 x64 和 ARM64 分别解压启动；检查托盘、退出、二次启动、开发版与日常版隔离。
2. 修改快捷键；尝试系统占用组合键，确认明确提示且旧设置保留。
3. 在 100% / 150% / 200% DPI、多显示器负坐标及跨屏排列下截图；确认无偏移、裁剪或错屏。
4. 浏览器打开无敏感内容的示例网页，保留 tooltip，触发截图，检查冻结画面保留提示。
5. 对箭头、圆形、文字、裁剪、打码分别操作并撤销/重做；复制到画图、保存 PNG，确认实际像素与预览一致，打码无法从导出图撤销。
6. 浏览器、微信和 Codex 的静态对话分别连续滚动；确认目标保留滚动焦点、预览增长、边框与按钮不进入长图。
7. 快速滚动、反向滚动、重复内容及页面重排；确认显示恢复提示，可回到锚点接续、撤销或明确确认只导出已有内容。
8. 采集中按 Esc、退出程序、锁屏和调整显示器；确认没有残留遮罩、热键或后台采集。
9. 从较旧的真实 Windows 正式版检查更新；确认架构正确、确认后安装和重启、备份可恢复、不可写目录不提权。仅有一个版本时不能完整验收版本更新。
10. 网络中断、错误校验清单、异常 ZIP、替换/启动失败时，确认旧版仍可用或可从备份恢复。无需关闭系统安全保护。

本机 macOS 交叉编译与合成测试不代替上述桌面验收。没有完成的项目应在 PR 中继续标为待验收。
